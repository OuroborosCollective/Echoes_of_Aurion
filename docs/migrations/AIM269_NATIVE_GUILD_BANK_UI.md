# Native guild bank bridge (AIM-253 / AIM-269)

The native AX1 character menu and community dock now open the existing authenticated Aurion guild bank. Guild creation serializes on the owner profile and commits guild plus founder membership in one transaction. A repeated identical creation resolves to the same guild; a conflicting second active membership is rejected. Guild/member IDs derive from owner, prior founder count and submitted names, without clock or random input.

The readback returns bounded, owner-validated wallet/treasury balances, legacy and V2 inventory, held custody, actual capabilities, three resources and all six authored building definitions. Reads use a consistent transaction. Oversized item sets require explicit pagination rather than silently omitting custody. The view has loading, stale, error and retry states and retains the existing server authorization and receipt checks.

Each bank mutation requires a visible preview and explicit confirmation. SHA-256 intent keys bind owner, guild, bank revision, persisted planning count, operation and canonical payload. The apply request sends only the confirmed hash. A lost response retains that hash, including when polling already sees the completed revision; retries retrieve the original receipt. Building previews display their resource cost and resource donations disclose consumption. Real expiry clocks on server-side plans remain enforced.

Validation at publication: TypeScript passes; 539 local tests pass, 51 database-gated tests skip locally. UI tests verify no apply before confirmation, a completed operation with a lost response and advanced readback, exact hash replay, foreign previews and invalid decimals. Two added MariaDB tests cover concurrent founding and rollback if membership insertion fails. The existing guild transaction suite now validates the client readback contract and rejects non-isolated databases before fixture cleanup. Browser coverage extends the actual registered player's quest flow with founding, preview without mutation, deposit, withdrawal and item custody roundtrip, checking four physical receipts and one canvas. Actual MariaDB/browser CI results are required before merge.

This bridge does not implement the remaining governance, territory or kingdom UI, autonomous NPC economy, dungeon groups or housing. Backend AIM-268/AIM-269 acceptance remains separate from the overall migration completion.
